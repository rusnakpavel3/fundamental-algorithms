# Фундаментальные алгоритмы — лабораторная работа №1

Решения задач лабораторной работы №1 курса «Фундаментальные алгоритмы» на языке C (стандарт C99).

Каждая задача — отдельный самостоятельный CMake-проект в своей папке. Все решения собираются без предупреждений с флагами

```
-std=c99 -Wall -Wextra -Wpedantic -Werror
```

## Общие принципы

- Программа никогда не завершается аварийно; `exit()` и `abort()` не используются.
- Логика (вычисления, обработка данных) отделена от ввода-вывода: функции логики ничего не печатают и не читают.
- Функции возвращают статус-код (`enum Status`), результат — через параметры-указатели.
- Проверяется всё: количество и формат аргументов, числа (`strtol` / `strtoll` / `strtod` с проверкой `endptr` и `errno`), указатели, переполнения — до выполнения операции.
- Каждый `malloc` и `fopen` проверяется, память освобождается и файлы закрываются на всех путях выполнения.
- Вещественные числа сравниваются через `eps`, переданный параметром.
- Вещественные числа на вводе — не больше 15 значащих цифр (столько гарантированно хранит `double`, константа `DBL_DIG`); иначе число отклоняется, чтобы программа никогда не работала с числом, отличным от введённого. `eps` — строго между 0 и 1.
- Глобальных переменных нет.

## Сборка

### CLion

1. File → Open → выбрать папку задачи, например `task1_3` (ту, где лежит `CMakeLists.txt`).
2. Run → Edit Configurations → **Program arguments** — аргументы командной строки.
3. Для задач с файлами (1.4, 1.7, 1.8) в **Working directory** указать папку задачи (`$ProjectFileDir$`): иначе относительные имена файлов ищутся в `cmake-build-debug`.
4. Для 1.10 можно включить **Redirect input from** → `input.txt`.

### Командная строка (CMake)

```
cmake -S task1_3 -B task1_3/build
cmake --build task1_3/build
```

### Командная строка (gcc напрямую)

```
gcc -std=c99 -Wall -Wextra -Wpedantic -Werror task1_3/*.c -o lab1_task3 -lm
```

На Windows (MinGW) для корректной работы `%lld` и `%zu` нужно ещё `-D__USE_MINGW_ANSI_STDIO=1` — в `CMakeLists.txt` это уже сделано. Программы переключают консоль Windows в UTF-8, чтобы русский текст выводился правильно.

## Проверка утечек памяти

Динамическая память используется в 1.2 (решето для γ), 1.4 (имя выходного файла) и 1.9 (массивы A, B, C). Все пути выполнения, включая ошибочные, проверены valgrind: утечек и ошибок нет.

```
valgrind --leak-check=full --error-exitcode=1 ./lab1_task9 -10 10           # Linux / WSL
drmemory -- lab1_task9.exe -10 10                                           # Windows (Dr. Memory)
```

Для Dr. Memory программу на MinGW лучше собирать с отладочной информацией в формате, который он понимает: `-g -gdwarf-2`.

## Задачи

### 1.1 — действия над числом

Флаги: `-h` — числа от 1 до 100, кратные x; `-p` — простое или составное; `-s` — шестнадцатеричные цифры; `-e` — таблица степеней 1…10 до степени x (1 ≤ x ≤ 10); `-a` — сумма 1…x; `-f` — x!. Вместо `-` можно писать `/`.

```
> lab1_task1 97 -p
97 является простым числом.
> lab1_task1 255 -s
F F
> lab1_task1 20 -f
20! = 2432902008176640000
```

Переполнения проверяются до вычисления: `21 -f` сообщает о переполнении, а не печатает неверное число.

### 1.2 — константы с точностью eps

Для каждой из пяти констант — предел, ряд (или произведение) и решение уравнения дихотомией. Результат считается успешным, только если ошибка гарантированно меньше eps; иначе программа честно сообщает «не сошлось». Допустимый eps — от 1e-14 до 1 (не включая).

```
> lab1_task2 1e-6
eps = 1e-06 (знаков после запятой: 6)
e:
  предел: 2.718282 (шагов: 22)
  ряд: 2.718282 (шагов: 10)
  уравнение: 2.718282 (шагов: 22)
...
```

Для γ все три формулы из условия сходятся медленно: ответ есть только при грубом eps — примерно от 1.5e-2 для предела, 5e-4 для ряда и 3.6e-3 для уравнения.

### 1.3 — уравнения, кратность, треугольник

- `-q eps a b c` — решить a·x² + b·x + c = 0 для всех уникальных (с точностью eps) перестановок коэффициентов.
- `-m x y` — кратно ли x числу y (оба ненулевые целые).
- `-t eps a b c` — могут ли числа быть сторонами прямоугольного треугольника.

Коэффициенты и стороны могут быть сколь угодно большими или малыми в пределах `double`: перед вычислениями они делятся на наибольший по модулю, поэтому промежуточные величины (b², 4ac, a² + b²) не переполняются. Сравнение с eps — абсолютное, но допуск не бывает меньше погрешности самого `double` для чисел такого порядка.

```
> lab1_task3 -q 1e-6 1 -3 2
Уникальных перестановок: 6
1) (1)*x^2 + (-3)*x + (2) = 0: x1 = 2.000000, x2 = 1.000000
...
> lab1_task3 -m 21 7
21 кратно 7
> lab1_task3 -t 1e-6 5 3 4
Могут: гипотенуза 5, катеты 3 и 4
```

### 1.4 — обработка файла

Флаги: `-d` — удалить арабские цифры; `-i` — для каждой строки число латинских букв; `-s` — для каждой строки число символов, кроме латинских букв, цифр и пробела; `-a` — символы, кроме цифр, заменить hex-кодом ASCII. Без `n` результат пишется в `out_<имя>` рядом со входным файлом, с `n` (`-nd`, `-ni`, …) — в указанный файл. Входной и выходной файлы не могут совпадать: проверяется не строка пути, а сам файл на диске (на Windows — номер тома и индекс файла, на Linux — устройство и inode), поэтому `test.txt`, `./test.txt`, `папка/../test.txt`, полный путь или ссылка распознаются как один и тот же файл. Так же устроена проверка в 1.7 и 1.8.

```
> lab1_task4 -d test.txt          # результат в out_test.txt
> lab1_task4 -ni test.txt counts.txt
```

### 1.5 — ряды и интегралы

Ряды (в точке x): xⁿ/n!, (−1)ⁿx²ⁿ/(2n)!, 27ⁿ(n!)³x²ⁿ/(3n)!, (−1)ⁿ(2n−1)!!x²ⁿ/(2n)!!. Члены считаются рекуррентно, через отношение соседних членов, без факториалов. Интегралы на [0; 1]: ln(1+x)/x, e^(−x²/2), ln(1/(1−x)), xˣ — методом средних прямоугольников с удвоением числа отрезков.

```
> lab1_task5 1e-6 0.5
Суммы рядов:
  a) x^n / n!                              = 1.648721   (членов ряда: 8)
  b) (-1)^n x^(2n) / (2n)!                 = 0.877582   (членов ряда: 4)
  c) 27^n (n!)^3 x^(2n) / (3n)!            = 2.900487   (членов ряда: 14)
  d) (-1)^n (2n-1)!! x^(2n) / (2n)!!       = -0.105573   (членов ряда: 9)

Интегралы на [0; 1]:
  a) ln(1 + x) / x                         = 0.822467   (отрезков: 512)
  b) e^(-x^2 / 2)                          = 0.855624   (отрезков: 512)
  c) ln(1 / (1 - x))                       = 1.000000   (отрезков: 1048576)
  d) x^x                                   = 0.783430   (отрезков: 2048)
```

### 1.6 — переменное число аргументов, степень, дихотомия

Программа без аргументов: `main` вызывает все шесть функций на заготовленных примерах — корректных, граничных и ошибочных — и печатает результат или текст ошибки.

- `is_convex_polygon(&convex, eps, n, x1, y1, ..., xn, yn)` — вершины в порядке обхода; выпуклый, если все повороты в одну сторону и суммарный поворот равен одному обороту (звезда — невыпуклая). Сравнивается синус угла поворота, поэтому результат не зависит от масштаба координат.
- `polynomial_value(&value, x, n, a_n, ..., a_0)` — схема Горнера.
- `find_kaprekar(found, capacity, &found_count, &bad_index, base, count, "s1", ...)` — общее определение (разрез квадрата в любом месте), основания 2…36, числа до 4294967295.
- `geometric_mean(&value, count, x1, ...)` — через логарифмы мантисс и сумму двоичных порядков, без переполнения; отрицательные числа — ошибка.
- `fast_power(&value, x, n)` — рекурсивное быстрое возведение, промежуточные значения в `long double`; переполнение, исчезновение порядка и 0 в отрицательной степени — статусы.
- `bisection(&root, f, a, b, eps)` — корень с погрешностью не больше eps; на концах нужна смена знака.

Вещественные аргументы функций с `...` нужно писать как `1.0`, а не `1`: тип вариативных аргументов компилятор не проверяет.

### 1.7 — лексемы

- `-r f1 f2 out` — лексемы из двух файлов поочерёдно.
- `-a in out` — каждая 10-я лексема: строчные буквы и ASCII-коды по основанию 4; каждая 2-я — строчные буквы; каждая 5-я — ASCII-коды по основанию 8.

```

one A two B three C four D E F G
> lab1_task7 -a tokens.txt result.txt
Hello world ABC def 061101 ghi Jk lm No 13001301 Rs tu
```

### 1.8 — минимальное основание

Для каждого числа из входного файла в выходной пишется строка: число без ведущих нулей, минимальное основание системы счисления (2…36) и значение в десятичной системе. При ошибке сообщается номер неверного числа.

```
> lab1_task8 numbers.txt result.txt     # фрагмент result.txt
...
ff 16 255
Zz 36 1295
-A 11 -10
...
```

### 1.9 — случайные массивы

Часть 1: массив из 20 случайных чисел в диапазоне [a; b], минимум и максимум меняются местами. Часть 2: массивы A и B случайной длины 10…10000 со значениями в [−1000; 1000]; C[i] = A[i] + ближайший к A[i] элемент B (сортировка копии B и бинарный поиск).

```
> lab1_task9 -10 10
```

### 1.10 — системы счисления

Сначала вводится основание 2…36, затем числа в этой системе (цифры больше 9 — прописными буквами) до слова `Stop`. Неверные числа пропускаются с сообщением. Ведущие нули допускаются в любом количестве. Сумма копится без переполнения промежуточных значений; если итог не помещается в `long long`, программа сообщает об этом, а максимум по модулю всё равно выводится. В конце печатаются максимальное по модулю число и сумма — в исходной системе и в системах 9, 18, 27, 36.

```
> lab1_task10 < input.txt
...
Введено чисел: 4
Максимальное по модулю (основание 16): -FFF
...
Сумма (основание 16): -F13
```
